## 2026-08-03, foundation gauntlet correction

**Failed gauntlet, fixed before merge**

The first executable manifest draft used local enum names such as `critical`,
`high`, `source-controlled`, and `externally-owned`. An architecture critic
rejected it against plan section 16.4. The contract now uses the exact
`journey-critical` / `supporting` / `utility` criticality values, all ten
approved dispositions, all five delivery states, and the approved manifest
types. Rows now carry dependencies, flags, target profiles, required evidence,
production probes, evidence metadata, rollback boundaries, and applicable
states.

**Implemented**

Added `legacy-baseline.json` beside the machine manifest. It contains only
hash-specific, design-era-tagged legacy records and is excluded from active
discovery. The current baseline has 386 named legacy records across the
authoring, web, native, renderer, prompt, and marketing roots.

**Known pending evidence**

The manifest is inventory-complete and source-fingerprint-complete, but pixel,
interaction, performance, accessibility, provider, and public-cache evidence
are explicitly marked pending until the dedicated channel gauntlets land. No
row is labeled preview-accepted or production-accepted from source inspection.

**Dependency correction**

The foundation critic also found that #715's final deletion requirement creates
a cycle with #720 and #724. Font readiness must be separated from final legacy
font deletion, with deletion verified by each surface child and #729. Native
visual rollout also remains gated by #631 and the Android Phase 0 ruling; this
baseline records the existing future-Android ruling as intentionally unreleased
with compile and no-Google-Play-distribution guards, not as shipped Android.
