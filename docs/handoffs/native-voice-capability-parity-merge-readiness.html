1. The mental model

Before

Realtime voice was its own smaller product

  1. The realtime model received six copied tool definitions.
  2. A custom route called those six tool modules directly.
  3. Instructions explicitly refused printables, binder, planner writes, calendar writes, and delivery.
  4. Tool results never entered the native overlay message stream.
  5. Question-card answers exited voice instead of continuing the conversation.

After

Realtime voice is an audio front door to normal Homa

  1. The realtime model receives one function: ask_homa.
  2. The API persists the exact spoken source turn before any action.
  3. A short-lived signed bridge enters the authenticated mobile Eve channel.
  4. Eve loads family context, fleet skills, and the ordinary 64 bounded tools.
  5. Completed authored tool results return as native overlay events.
  6. The audio model reads Eve's exact short reply with tools disabled for that response.
  7. Question-card taps continue the same Eve session.

2. Non-obvious behaviors

The bridge has proof, not privilege

WhatThe bridge request is HMAC-bound to the caller access token, canonical source-message UUID, SHA-256 of the exact spoken text, and a 60-second timestamp.
WhyThe inner Eve turn may reuse the already-persisted source message only when code proves it is the same authenticated turn. The model never supplies familyId.
Whereapps/web/lib/voice/voice-bridge-auth.ts:39, apps/web/agent/channels/eve.ts:136, apps/web/agent/channels/eve.ts:203

One spoken turn, one canonical history row

WhatThe route persists the current voice turn before delegation. The private bridge turn can read recent continuity, but skips normal continuity mutation, assistant classification, and duplicate conversation persistence.
WhyJournal evidence needs real parent provenance, while an internal execution turn must not create a second episode or claim the same reply twice.
Whereapps/web/app/api/voice/realtime/tool/route.ts:94, apps/web/agent/channels/eve.ts:275, apps/web/agent/hooks/persist-conversation.ts:16

The phone renders results, not promises

WhatOnly completed, non-error Eve tool results become effects. Mobile validates the response, deduplicates call IDs, and converts effects into the same dynamic-tool message shape its overlays already understand.
WhyThis reuses planner, material, question, hours, and receipt UI without inventing a parallel voice protocol or showing failed actions as successful.
Whereapps/web/lib/voice/homa-bridge.ts:86, apps/mobile/src/features/voice/realtime-tool-effects.ts:26, apps/mobile/src/features/voice/use-voice-session.ts:208

Eve owns the answer after an action

WhatAfter ask_homa, realtime receives a response override that disables every tool and instructs it to read only spokenReply, exactly once.
WhyThe audio model should handle turn-taking, but it must not paraphrase a verified result into a stronger claim or recursively call another tool.

3. Existing behavior this leans on

Eve remains the capability and policy authority. The bridge does not bypass billing gates, family context, fleet-skill routing, tool schemas, tool deadlines, or per-tool tenant re-scoping. If a normal mobile chat tool is unavailable for a real reason, voice is unavailable for that same reason.
This is an OTA change, not a native capability addition. The current fingerprint c074fbd55ccfed66decc1c3b7ab4b656506690a9 matches finished EAS production build 16. The main workflow still has to publish a production update with that runtime after merge. App Store Connect must separately confirm that build 16 is the binary families actually install.
Live voice deliberately has no photo picker, details form, or checklist screen. Homa asks a short spoken question, uses the native question card, or asks the parent to switch to chat when a photo itself is essential. The app hides ask_for_photo as a backstop so it cannot become a fake “done” receipt.
Local simulator launch is not part of the green evidence. Hermes export succeeds, and EAS compiled a finished store binary at the matching fingerprint. The ignored regenerated local workspace fails inside React Native 0.85.3 codegen under local Xcode 26.6 because Folly headers are absent before Homa links. That environment failure is not presented as an app launch.
