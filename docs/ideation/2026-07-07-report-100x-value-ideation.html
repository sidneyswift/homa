Grounding Context

new baseline · shipped since the first pass (2026-07-07, small hours)

The LLM narrative layer is built end to end (flag-gated, uncommitted). Migration 20260707030725 adds narrative + narrative_meta to lead_reports and lead_plans. The facts payload (narrative-facts.ts) hands the writer the parent's whatsWorking notes keyed by subject name, helpWith, merged interests, code-computed movement lines, and per-subject observation counts, confirmed skills, and next steps; allowedNumbersFrom derives the gate's digit allow-list from the serialized payload itself. The gate (narrative-gate.ts) enforces per-piece caps, banned words, sibling names, diagnosis substrings, and invented-number rejection, and fails the whole generation when the note or synthesis rejects or more than 4 subject lines do. The runner claims single-flight with a 10-minute stale self-heal; the score route answers instantly, then writes the narrative in after() and sends the report email only when generation lands, so the emailed link always opens a finished report. Plan narratives (intro, 4 week lines, closing) run through the same gate. Sample and red-team fixtures are committed at prompt v2026.07.2 with a version lock in check:map; the privacy page now names Anthropic as a processor and the method page says plainly that Homa writes the words around code-computed numbers. REPORT_NARRATIVE_ENABLED defaults off until the founder read-aloud.

The family workspace bridge shipped (uncommitted, live e2e verified). Every score runs ensureFamilyWorkspace: a real family via the create_my_family RPC, children mirrored from lead kids with real birth dates, profiles mirrored forward on rescore, and a one-time what_works memory seeded from the parent's whats-working notes, all as the signed-in caller under RLS. A report holder with an auth session now has a live /home and /chat whose agent already knows her kids the moment the first report exists.

What the re-baseline changes in this doc. Ideas 1 and 3 got materially cheaper (the pipeline they extend now exists and their remaining gaps re-verified this morning: the writer still never sees archived narratives, and PlanFacts still lacks whatsWorking and curriculums). Idea 4's raw material now accrues automatically (every rescore archives the era's words next to its numbers). Idea 5's editions ride a now-proven generate-gate-store pattern. highConfidence still has zero consumers in apps/web (re-verified), so idea 2's basis stands, though the writer can now at least be honest about thin evidence in prose.

Codebase context. The report: a parent answers a ~5 minute observation questionnaire per child; a deterministic scorer (packages/core/src/map/, 220-item cited bank, 16 subjects) produces positions and months-ahead; the report page renders a note, strengths-first cards, a chart, receipts drawers, growing activities, and 4-week plans at a permanent token URL. The D8 overturn rules that the model writes every parent-facing word from a deterministic facts payload; numbers, positions, and ages stay code forever. Founder rulings on record: "lean into intelligence, while capturing data correctly... building homa into an 'agent' for the user that is personal to them" and "I would rather the report and the deep dives and the 4 week ciricculums be FUCKING INCREADIBLE, then have it take less than 20 seconds."

What the evidence scouts found (first pass, still true unless noted in the baseline box): a shipped promise the code does not keep ("I'll fold it into the plans" while the plan builder receives only interests and style), a computed confidence signal with zero consumers, a 12-snapshot history archive of which the UI reads exactly one entry, plan check-offs living only in localStorage, a seeded 51-jurisdiction state requirements table surfaced as one teaser line, and a correction channel that is a mailto.

External context. Research value high: parents act on reports when a specific gap is visible, and vague or inflated reports produce no action; numbers change parent behavior where prose alone does not. Prior art: ASQ-3 parent reports, IXL diagnostics, Seesaw portfolios, NZ Learning Stories (narrative assessments kept as keepsakes), Wrapped and Duolingo recap mechanics. Named white space: one artifact that is simultaneously validated scoring, narrative keepsake, compliance-adjacent evidence, and a hand-to-grandma object; nobody ships that combination.

Homa the correspondent: a report that remembers

axis · what-it-saysconfidence 90%complexity low-medium
Description
Feed the archived narrative (the last note, the last next step Homa pointed at) back into the facts payload, so every rescore writes chapter N of a correspondence instead of a stateless first letter: "Last month I pointed at letter names; you ran with the letter hunt, and here is what moved." Add one new piece: a dated, printable Learning-Story letter addressed to the child herself, built from her strongest observed statements and the parent's own whats-working notes quoted back, with no numbers, made for the memory box. On the new baseline this is a narrow, well-bounded change: extend getReportNarrativeSource to select the archived narrative out of history, add a prior-letter field to ReportFacts, one new section in report-writer.md, one new schema key and gate cap for the keepsake, bump REPORT_PROMPT_VERSION, regenerate fixtures for the read-aloud. The bridge gives the correspondent a second surface: the same whats-working words the report quotes are now seeded as the chat agent's what_works memory, so the letter and the chat can genuinely sound like one person who knows this family.
Basis
direct: re-verified on the shipped code: getReportNarrativeSource selects r.scores, r.history and ReportFactsInput.history is typed scores + dates only (narrative-store.ts:48, narrative-facts.ts:90), while every rescore archives the shipped words next to the old numbers and resets the live row (store snapshot layer); allowedNumbersFrom(facts) derives the allow-list from the payload (narrative-facts.ts:187-189), so prior-letter digits join it with zero gate changes. The bridge seeds what_works memories from the same notes (bridge.ts:338-377). external: NZ Learning Stories (Margaret Carr), narrative assessments families keep for decades.
Rationale
This is the founder's "agent that is personal to them" ruling made literal, and it is now the cheapest idea on the list relative to its ceiling: the pipeline, gate, versioning, and fixture loop it needs all shipped last night, and the committed Maya fixture already demonstrates the voice bar the memory feature would build on. Memory is what separates a correspondent from a report generator, and a letter worth keeping defeats the one-glance-and-discard failure mode in a way no scoring improvement can.
Downsides
Prompt surface grows (memory injection needs its own red-team pass so old advice is referenced, never contradicted). The keepsake register must survive the struggling-kid read-aloud. First reports have no history, so the memory section must degrade to silence, not filler. The severable "overnight second read" leg still collides with the no-sequences email doctrine and needs an explicit founder call if pursued.

2.

The living record: every touch is an observation

axis · what-it-knowsconfidence 80%complexity high
Description
One mechanic, four doors. Tap-to-correct: the owning parent changes any receipt answer in place (today the only correction channel is a mailto). The sharpness meter: surface the computed per-subject confidence in honest radiology grammar ("well observed" vs "one clear look so far") and let each thin subject ask its single highest-information question inline, one tap. The observation inbox: reply to the report email with one plain line ("she counted to 31 in the car") and it lands in the child's context; clear bank-item matches offer a one-tap confirm chip. The self-renewing report: on a return visit months later, the permanent URL knows the child has aged into new checkpoints and offers a 30-second pre-filled diff re-check ("In July you said she counted past 20 easily. Still true, or moved?"). Every door feeds the same pipe, and on the new baseline that pipe is real shipped code: deterministic rescore, archived history, regenerated words behind the writing beat, with the status endpoint and single-flight claim pattern ready to reuse for any of these triggers.
Basis
direct: highConfidence is computed at scoring.ts:127 and re-verified this morning to have zero consumers in apps/web; the writer now receives per-subject observations counts (narrative-facts.ts:28) so prose can be honest about thin evidence, but no UI meter or inline question exists; correction channel is a mailto (report-actions.tsx:57-62); only the first view of the permanent URL is ever stamped (store.ts:713-715); the diff re-check mechanic is already designed for invite day (journey BEAT 8) and just never applied to the report itself. external: IXL's diagnostic keeps parents answering because the meter visibly sharpens.
Rationale
A first report rests on as few as 16 taps, and its known weakness is thin evidence presented with a confident face. This flips the report's identity from one-shot transcript to co-maintained ledger: every parent touch makes it sharper, every rescore regenerates the story, and the free artifact becomes the habit the paid product inherits. The narrative layer raises the payoff of every touch: a corrected answer now rewrites the words, not just a badge.
Downsides
Largest engineering surface of the six (inbound email parsing is its own project; ship the doors in stages). Every write path from a shareable URL must sit behind the existing session gate or any link holder could mutate a child's record. More asks on the page risks nag; the meter must stay an offer, never a scold. Each touch that rescores also regenerates (cost is ruled a non-constraint, but the writing beat becomes a repeated experience worth designing).

The default-on month, with one consent tap

axis · what-parent-doesconfidence 80%complexity medium
Description
Three fixes that make the report's action loop real. First, keep the shipped promise, now a small precise change: the whats-working form says "I'll fold it into the plans for the growing subjects," and on the new baseline the report note and synthesis DO quote those notes, but the plan still does not: PlanFacts carries only interests, style, starting line, targets, and weeks, and the deterministic builder still receives only interests + style. Extend getPlanNarrativeSource and PlanFacts with whatsWorking, curriculums, and helpWith, and teach the plan section of report-writer.md to credit the family's own proven strategies. Second, give the month a memory: persist plan check-offs to the plan row (today localStorage-only) and render a positive-only "your month" panel beside the movement chips at retest, with a 10-second "which of these did you get to?" chip question. Third, make the loop near-default-on: the report ends with one consent tap, "want me to build the month and check back in 4 weeks?", instead of hiding THE move behind a drawer click.
Basis
direct: re-verified on the shipped code: PlanFacts has no whats-working or curriculum fields (narrative-facts.ts:57-68), getPlanNarrativeSource selects interests + family style only (narrative-store.ts:168-212), and buildFourWeekPlan is still called with { interests, style } (store.ts:591-595), while ReportFacts.whatsWorking now exists and flows to the report writer (narrative-facts.ts:48); plan-weeks.tsx:8-11: "the retest email is the loop's real memory"; plan, retest clock, and retest email exist only behind a click (store.ts:504-512, 630-645).
Rationale
The plan is the report's main action surface, its narrative now exists (intro, week framings, closing through the same gate), and the remaining gap is exactly the facts it is fed. The verifier flagged silent auto-arming of the retest email as a collision with the explicit-ask email doctrine; the one-tap consent keeps the doctrine intact while converting the loop from opt-in-if-you-find-it to offered-to-everyone. A remembered month makes "your work is showing up in the numbers" evidence instead of assertion.
Downsides
Server-side check-offs add a write path that must stay session-gated. The consent tap adds one decision to a page that works hard to feel calm. Feeding more family context into plan facts widens the gate's surface slightly (whats-working text is parent-authored free text; the gate already screens generated output, not inputs).

4.

The growth curve and the growth story

axis · over-timeconfidence 75%complexity medium
Description
The report archives up to 12 dated snapshots per child, and on the new baseline each snapshot carries the era's generated words next to its numbers (the rescore path resets the live narrative and archives the old one). The UI still reads exactly one entry. Draw the rest: a per-subject dated curve in the pediatric growth-chart grammar (the child against her own past, never against another child), a compiled growth-story view that walks the whole arc with excerpts of what Homa wrote in each era, and once a year, a growth edition that reads like a year in the life. The retest email's promise becomes "a new dot lands on her chart."
Basis
direct: HISTORY_CAP = 12 with narrative-era snapshots archiving their words (store.ts:391-402) while the render path reads only history[0] (report-view.tsx:141); movement lines are already computed for the writer (narrative-facts.ts:95-121); "one year of growth" is an alternative pass condition in NY and WV, "growth framing is not just kind, it is legally load-bearing" (state assessment notes). external: pediatric growth charts, the one sparse-data instrument parents already trust for decades; Wrapped-style annual recaps as a self-propagating ritual.
Rationale
The product's promise is "watch the numbers move," and the artifact currently shows one delta chip. The curve is inherently anti-comparison (voice law), it is the honest answer to single-anchor spread limits, and it makes "this report is the before picture" literal: the paid product is the thing that keeps drawing the curve. Every idea above this one feeds it: corrections, re-checks, and consented months all mint new dots and new chapters.
Downsides
Most leads have 0 or 1 snapshots until the rescore loops run, so the surface must degrade gracefully to a single dot. Growth praise must scale by age band (a flat middle-school reading curve is normal and must never read as a problem). The annual edition needs a deliberate call against the email doctrine (one promised anniversary artifact, not a sequence).

The proof stack: state card, audience editions, photo receipts

axis · other-audiencesconfidence 70%complexity high
Description
Make the report the family's evidence system. The state card: render what the family's state actually asks, the next real deadline (VA Aug 1, WV Jun 30, NY quarterly), and where scores go, from the 51-jurisdiction table already seeded in prod, always with the explicit boundary that the report never satisfies a state instrument. Audience editions: the token page stays the parent's private letter, and purpose-built renditions of the same deterministic facts serve the named skeptics: a spouse one-pager (hard numbers, per-year math), a grandma packet (self-contained, no login), an evaluator evidence pack (composite growth framing, citations, the 89 verified standards codes the report currently collapses into source labels). On the new baseline each edition is one more schema, prompt section, and gated store on a proven pipeline, not new infrastructure. Photo receipts: attach a photo of the actual work to any answer, rendered inside that receipt strip, never scored, seeding the portfolio families in evaluator states already need.
Basis
direct: the compliance surface today is one teaser line (report-view.tsx:623-628) while state_requirements is seeded (migration 20260707032148) and the bridge now carries us_state into the real family (bridge.ts:209-212); the generate-gate-store pattern shipped (narrative-generate.ts, narrative-gate.ts, narrative-store.ts) and the privacy page already names the AI writer honestly; D7: tokens deliberately unhashed because "the URL itself is the shareable artifact... sharing is the marketing"; the planning corpus names every audience (spouse one-pager, Grandma Sue "the packet, not the product", the mother-in-law hearing as "the sleeper marketing asset"); no upload code exists anywhere in onboarding (verified by grep). external: families pay evaluators $30 to $100 per student; Seesaw built a company on capture-to-portfolio.
Rationale
Compliance fear is the sharpest named anxiety in the ICP research, and the report is where that fear lives. One report becoming N audience-shaped artifacts is the D7 thesis executed rather than hoped: every edition that leaves the house recruits exactly the audience that currently blocks adoption.
Downsides
Hard privacy escalation on photo receipts (minors' media on permanent unauthenticated URLs needs its own access controls, private-by-default). The state card needs the family's homeschool route, which the flow does not collect yet (assessment duty attaches to route, not state). Legal-tone bar on the evaluator pack is unforgiving; scope which two editions ship first.

Draw the map: bands and lit paths, not dots and badges

axis · what-it-knowsconfidence 70%complexity medium
Description
Two honesty upgrades to the report's core display. Bands, not dots: each receipt renders the national benchmark as a typical window ("most kids: between 3y and 4y 6m") instead of a single verdict dot, populated where sources support it with the dot as fallback. The lit path: each subject drawer draws the ladder the scorer already climbs, confirmed anchors lit, the frontier glowing as "next up," one or two nodes above with their typical-by ages, nothing past the +24 month cap and no locked-state language. Unchanged by the new baseline: this is deterministic display work the narrative layer does not touch, though the writer's per-subject next-step facts and the path view would tell one consistent story.
Basis
direct: "single-anchor displays understate normal spread" and the CDC-75th-percentile vs median mixing debt are on record in the benchmark synthesis (00-synthesis.md:61, 107); the ladder mechanics exist (bank.ts:8-12: an "easily" unlocks the next item up the ladder) and the plan already computes floor and target (plans.ts:231-232). external: Duolingo path mechanics; growth-chart percentile bands.
Rationale
The single dot is simultaneously the report's main anxiety generator (a "not yet" past the dot reads as a binary miss) and its main precision overstatement. A band makes on-track genuinely reassuring while keeping real gaps specific enough to act on; the lit path makes the deep dive and the 4-week plan legible as moves along a drawn road. The copy already claims the numbers are a map, never a grade; this is the UI finally drawing the map.
Downsides
Band metadata is per-item editorial work against the bank (start where sources give ranges). A path view must be designed hard against gamification creep: no locks, no streaks, no levels vocabulary. Closer to a strong render upgrade than a step function on its own; it earns rank 6 by de-risking every other idea's display honesty.
