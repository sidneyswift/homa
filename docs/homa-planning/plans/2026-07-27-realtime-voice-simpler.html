The reframe you were reaching for

I called it "two brains" and then designed a CI guard to keep them in sync. That was the wrong frame. Homa is not a model. Homa is a context builder, a tool registry, and a memory. The model is a voice.

And the codebase already agrees. Across all 61 tool files, ctx is touched in exactly five ways: session.auth.current.attributes (75 times), session.id (8), session.turn.id (4), channel.kind (4), channel.metadata (4). That is it. Whoever wrote these tools kept them transport-agnostic on purpose.

So there is one brain and two mouths, and most of the "adapter layer" I scoped is a function that builds an object with five fields.

Amends #275

6. I did not ask whether Telnyx can actually do this.

The whole "OpenAI holds the media, we never run an audio server" advantage assumes Telnyx will SIP-forward our number to sip.api.openai.com. Telnyx's own published guidance for OpenAI Realtime points at media streaming over a WebSocket bridge you run yourself, which is precisely the thing we are trying to avoid.

What is actually verified OpenAI documents the SIP path and Twilio and Bandwidth both publish carrier-side setup for it. Telnyx supports <Dial><Sip> to external SIP URIs in general. What is not verified is Telnyx forwarding cleanly to OpenAI with caller ID intact. If it cannot, the fallback is not "run a bridge on Vercel" (that is the 800s cap plus 8 kHz to 24 kHz transcoding). It is keep Telnyx for SMS and 10DLC, which is a lot of invested setup, and get a voice number from a carrier that documents the OpenAI SIP path.

Costs: nothing, it is one more thing the spike already had to try. Buys: we find out in half a day rather than three days into arc D.

The XL option

The maximal version of your instinct: extract lib/homa-core holding context assembly, the tool registry, instruction composition, and memory write-back, with eve demoted to one consumer among several. Architecturally that is the right shape and it is where this ends up in a year.

I do not think you should do it now. You get roughly 90% of the benefit from rungs 2 and 4 plus arc A, because the tools are already transport-agnostic (that is what the ctx audit proved). Doing the full version now means touching 61 tool files to prove a point, during the run-up to a fixed launch date, with #211 already open saying web and mobile are drifting. Buys: purity. Costs: a fortnight and a large diff across everything.
