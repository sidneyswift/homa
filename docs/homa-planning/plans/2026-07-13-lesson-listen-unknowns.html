Lesson listen · unknowns found before the first line of code

A blindspot pass over the decided plan (2026-07-13-lesson-listen.md). The task sounds like "record, transcribe, analyze, update progress on rails that all exist." What you are actually walking into: a scoring pipeline whose matcher was built to read a MOTHER'S SENTENCES, being fed a CLASSROOM TRANSCRIPT for the first time, plus a transcription vendor whose fine print both helps and hurts the plan. Every card below is bought with a file path or a vendor doc, and ends with the sentence that fixes the implementation prompt.

The one to read if you read nothing else: landmine 1. As written, LL-5 would ship a pipeline where almost every lesson quietly produces ZERO evidence rows, the same shape as the Noser incident that triggered the observation ledger, at 45 minutes of audio per occurrence instead of one text.

Does the plan survive?
Yes, with two amendments.

The upload, storage, consent, TTL, and review surfaces all stand as planned. LL-5 (analysis) needs a different extraction contract (landmine 1), and the pipeline wording gets simpler, not harder (missing concept). Nothing grows in size except LL-5, by roughly half a day.

Best surprise
The fallback file got cheaper and safer.

Telnyx STT takes files to 100MB and accepts a public file_url instead of uploaded bytes. Our Blob URLs are already public with random suffixes, so a 60-minute Voice Memos file never has to pass through a Vercel function at all (landmine 4).

Worst surprise
Our Whisper model returns text only.

No timestamps of any kind from openai/whisper-large-v3-turbo. The plan promised minute-stamped moments; time can only come from segment boundaries, which makes segment length a product decision, not a tuning knob (landmine 2, decision 2).

Landmine 1 · the big one

The journal matcher refuses dialogue: verbatim transcript quotes will score almost nothing

The whole evidence lane assumes lesson quotes flow through the journal path. But journal-matcher.ts only scores clauses whose SUBJECT is the child's name: childAttributedPredicates (line 237) anchors on ^Emma\s+, bails to "other" on any capitalized non-child actor (line 262, OTHER_ACTOR_PATTERN), and evidence-policy.ts (lines 5 to 10) routes "we read..." to activity_only before matching even starts. A real lesson transcript is "Mom: try the next one. Kid: I did it!", which contains no child-name-subject sentences at all. The observation ledger's own origin story proves how strict this is: Sara's sentence no_matched partly because "read" attributed to the parent (observation-ledger.md §2). Tests would not catch it because synthetic test quotes are always written in parent-report style.

Prompt fix: "The extraction emits PAIRS: a normalized child-attributed clause in parent-report style ('Emma read the whole page aloud without help') AS matcher input, plus the verbatim transcript excerpt and segment number as provenance. The server verifies the excerpt is a literal substring of the transcript AND that the clause shares enough meaningful tokens with its excerpt (reuse normalizeMeaningfulTokens, require overlap above a tested floor) so the model cannot launder invented claims through normalization. Store both; the review shows the excerpt."
Landmine 2

whisper-large-v3-turbo returns text only, so "minute-stamped moments" have exactly one clock: segment boundaries

The Telnyx API reference is explicit: openai/whisper-large-v3-turbo returns text only; segment timestamps need distil-whisper, and word-level timestamps plus diarization need deepgram/nova-3. Our transcribeAudio reads payload.text and nothing else (transcribe.ts line 110). The plan's moments timeline ("distracted around minute 20") can only be as precise as one segment. Nova-3 sounds tempting but its format allowlist is mp3 and wav only, and our recorder produces webm and mp4; riding the filename trick that saves AMR voice notes today (transcribe.ts header, verified live 2026-07-09) would double the blast radius of the day Telnyx starts trusting extensions.

Prompt fix: "Moments are stamped to the segment that contains them and phrased softly ('about 20 minutes in'). Do not switch STT models in v1; park a nova-3 diarization experiment as its own later ticket."
Landmine 3

Idempotency keyed by clause INDEX double-writes the day analysis retries

The plan keys evidence operations as lesson:{lessonId}:clause:{n}. Analysis is retried by design (claim column plus cron sweep), and a retried generateObject pass will not return clauses in the same order or count. Same clause at a new index writes twice; different clause at an old index silently replays the wrong receipt (claimOperationOrReplay short-circuits on key match, per progress-service.test.ts replay tests). The dispatch rails learned this exact lesson, which is why task runs key on (schedule_id, scheduled_for), not on position.

Prompt fix: "Key each evidence operation as lesson:{lessonId}:{sha256(normalizedClause)} so retries are stable regardless of order, and cap accepted clauses per lesson (12) so one hallucinating pass cannot spray operations."
Landmine 4

The fallback single file should never pass through our function: Telnyx takes a URL

A 60-minute Voice Memos m4a runs 30 to 60MB. Vercel caps request bodies near 4.5MB (the reason video/upload exists, per its own header comment), and pulling the blob into a function just to re-upload it to Telnyx burns memory and wall clock inside maxDuration = 300. The vendor docs close the loop: STT accepts file_url with the same 100MB cap, downloads server-side (15s download timeout), and requires a public URL with no auth headers, which is exactly what our random-suffix Blob URLs are. One catch: transcribeAudio only accepts bytes today.

Prompt fix: "For the fallback file, add an additive transcribeAudioUrl export beside transcribeAudio (new function, zero change to existing exports or callers) that posts file_url instead of bytes. Segments keep using the bytes path. Cap fallback uploads at 100MB with honest copy."
Unwritten convention 1

Progress writes go through runtime.ts or the MJ-08 events never fire

There are three layers that can record journal evidence and only one is correct for a server pipeline. The agent tool adapter is flag-gated and channel-shaped (tool-adapter.ts line 35). The service (progress-service.ts line 421) writes rows but emits nothing. Only runtime.ts line 103 wraps the call in withCommittedProgressEvents, which is where progress.evidence_recorded and progress.observation_saved actually fire after commit. A pipeline that calls the service directly would pass every unit test and silently produce zero analytics, which also blanks half the PMF signals in plan §8.5.

Prompt fix: "LL-5 calls recordJournalProgressEvidence from lib/child-progress/runtime.ts, never the service or repository directly, and gates the whole evidence lane on liveProgressEnabled() while the review write stays ungated."
Unwritten convention 2

Provenance columns assume a conversation exists, and a lesson is not one

Journal evidence provenance carries channel, messageId, and providerMessageId, and child_observations enforces channel in ('web','sms','email') plus a foreign key from message_id into conversation_messages (migration 20260713134500, lines 16 to 23 and 47 to 52). Lesson clauses have no conversation message, so inserts fail on the channel check the first time the pipeline runs against a real database, which the InMemory-repository unit tests will never show.

Prompt fix: "LL-1's migration extends the child_observations channel check with 'lesson' and the evidence source constraint with 'lesson_listen', message_id stays null for lesson rows, and the TypeScript unions in types.ts, view-schema.ts, and tool-result-contract.ts gain the same members in the same commit."
Missing concept

This repo has no "kick background work from a route" primitive, and lesson listen does not need one

The plan says segment registration "kicks a fire-and-forget transcription", but nothing in apps/web does that today: waitUntil appears only inside eve schedule handlers, call-memory runs inside the hourly cron, and narrative generation runs inline with a status poll. Inventing a fire-and-forget primitive here would be the first of its kind, unreviewed, in a feature that does not need it: a 3-minute segment transcribes in seconds, well inside a route's budget, and the recorder never waits on the response anyway.

Prompt fix: "No new async primitive. The segment-register route transcribes inline before responding (the client does not await it for UX), finish runs analysis inline under maxDuration = 300, and the hourly cron sweep is the only retry mechanism, with a bounded attempts column."
History note

The 3-minute dictation cap is a size law in disguise, and it sizes our segments

Dictation's 3 minutes exists to stay under 4MB "on iOS AAC bitrates" (dictation.tsx header): Safari ignores the 32kbps hint and records AAC at its own bitrate, several times fatter per minute than Chrome's Opus. A 5-minute iOS segment could run 4 to 8MB, which is fine for Telnyx (100MB) but is real upload time on the rural connections the personas call out. Shorter segments fix three things at once: upload size, crash-loss window, and landmine 2's moment resolution.

Prompt fix: "Copy dictation.tsx's MIME fallback chain exactly (webm opus, webm, mp4) and treat segment length as the moment-resolution dial; see decision 2."

Decision 1 · where does "Record a lesson" live?

The plan pins reviews to the kid page and chat but never says where recording STARTS. The kid must be picked before recording (evidence needs an unambiguous child_id), which makes kid-scoped surfaces natural. Real surfaces that exist today: the kid page (/app/{childId}, where "See all progress" already lives per kid-action.ts), the chat attach menu (chat-attachments.tsx), the planner, and tasks.

Decision 2 · segment length, which is also moment resolution

Because our Whisper returns no timestamps (landmine 2), a moment can only be located to its segment. Segment length trades moment precision and crash-loss window against upload chattiness.

Decision 3 · stay on whisper-turbo, or chase diarization now?

Telnyx's same endpoint offers deepgram/nova-3 with speaker labels and word timestamps, which would upgrade the moments timeline from inference to measurement. But its format allowlist is mp3 and wav only, so our webm and mp4 segments would ride the same filename trick that carries AMR voice notes today, and transcribe.ts's own header warns that trick breaks loudly the day Telnyx trusts extensions.
