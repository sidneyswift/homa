The photo desk: what a Google search key buys Homa

The founder handed over a SerpAPI key ("read their docs, decide what would be valuable, build it"). This is the record of what the codebase search found, the option ladder considered, what got built the same day, and the open questions the founder can still redirect. Everything below is grounded in real files and a live probe of the account.

Account reality, probed live 2026-07-13: FREE plan, 250 searches per month shared fleet-wide, 229 left, resets Jul 18. Whatever this key powers must be occasional, capped per family, and fail-soft. Paid plans lift the ceiling when a feature earns it.

The one real gap foundReal photographs. generate_image (gpt-image-2) owns illustration but cannot honestly photograph a monarch, real coins, or a workbook cover.
Text search already coveredweb_search is provider-run and was explicitly kept by the 2026-07-09 ruling. A second text-SERP tool would eat quota and confuse tool choice.
The plumbing already existeduploadStudioImageBytes() rehosts bytes into families/{id}/images/, and isFamilyArtifactUrl() then admits that URL everywhere family images work.
The hard constraintweb_fetch is disabled by founder ruling: arbitrary-URL fetch plus untrusted content is the exfiltration pair. Any design here must never let the model choose a URL.

M · new toolsBuilt today · the pick

Real photos for the materials studio: search_photos + keep_photo

Two-step: search_photos runs Google Images through SerpAPI server-side (safe search forced, unsafe results dropped, 10/family/day) and returns titles, sources, and sizes with HMAC-signed tokens, never URLs. keep_photo exchanges one token for a permanent copy in the family's own blob space; that URL then works in printables and as a generate_image reference with zero changes to those tools.

Found in code: the materials studio's path table has no honest answer for "real photograph"; Montessori-leaning families prefer real photography; isFamilyArtifactUrl() + uploadStudioImageBytes() made the safe version nearly free to build.

How the design maps to house law

Law / rulingWhere it lands here
web_search kept, web_fetch off (2026-07-09): no model-chosen URLsThe model chooses only a query to one fixed vendor host. Fetch targets come from HMAC-signed tokens over Google-authored result URLs; a prompt-injected model can at worst pick among returned results, never compose a URL that smuggles data out.
Tenant isolation: familyId never from model inputBoth tools resolve family from session auth; tokens are family-bound and rejected across families (tested).
Child safety / D4safe=active forced in code, unsafe results dropped, reverse image search rejected outright, queries are topic-only by binding instruction (the research-brief precedent; a code-level name guard was considered and dropped because kid names like "Story" false-positive on legit queries).
No executable content in family spaceRaster-only allowlist; SVG explicitly refused; 8MB stream cap.
Tool honesty + fail-soft notesEvery failure (unconfigured, quota gone, daily cap, dead link, oversized file) returns a note telling the model the honest next move.
Spend visibilityTwo typed events per the MJ-08 registry; searches are the scarce unit and every one is counted with its family and channel.
