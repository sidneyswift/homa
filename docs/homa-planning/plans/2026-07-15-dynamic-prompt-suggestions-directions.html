Decisions already made

Held constant in every direction

✓ One or two, always

Every eligible turn resolves to at least one pill. A deterministic fallback covers empty, invalid, or failed generation.

✓ Equal, short, and exact

Every pill has the same width and a 20-character limit. A tap sends that exact visible message.

✓ Cards take precedence

Hide generic pills while a direct question, progress choice, or camera card is active.

✓ Quality is evaluated twice

A strict offline rubric is primary. Taps and completed outcomes provide live evidence.

What a later implementation would reuse and add

Reuse from the current app

  • The docked row and composer in apps/web/app/app/chat-client.tsx.
  • The existing onFinish seam after a successful assistant turn.
  • The normal sendMessage path so a tap is a visible parent message.
  • latestProgressMessageInteraction and latestSnapRequest for action precedence.
  • The markdown prompt plus schema-constrained generation pattern in memory-extractor.md and extract-memories.ts.

New work, clearly separate

  • A founder-editable suggestion judgment prompt, strict 1-to-2 schema, 20-character limit, deterministic fallback, and prompt version.
  • An authenticated post-turn endpoint that returns suggestions to the open client instead of running only in after().
  • A small client policy that clears stale suggestions on send, failure, session rotation, or a newer action card.
  • Typed events for shown, tapped, and useful-outcome evidence, with no message content in the event payload.
  • Fixture transcripts, deterministic rubric checks, and a paid live-model drift eval modeled on the research-brief harness.
