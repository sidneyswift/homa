What the request sounds like

Let an existing parent retake the onboarding assessment over text.

What the system actually needs

A child-scoped, purpose-scoped session that asks the next useful question, saves each response, pauses safely, resumes across surfaces, and publishes one coherent report update.

The abstraction shiftone shared engine

Today: onboarding owns the questionnaire, SMS signup owns a second adapter, and chat owns one-item observations.

Recommended: a progress check-in module owns selection, session state, evidence, and publication. Surfaces only open, answer, pause, stop, and render.

Three architecture laws

  • Conversation history may explain a turn, but it must never be the workflow state.
  • Every response saves immediately, while report history publishes once per coherent check-in.
  • The report is a read model. Durable truth is dated evidence grouped into check-ins.
Do not reuse record_observation as the loop It calls createReport after each item. createReport archives on every call and retains only 12 prior snapshots. A 16-question text sitting could consume the visible history by itself.

How the score is calculated

  • Easily earns the conservative item anchor, using the early edge of a cited typical window when one exists.
  • Getting there earns the anchor minus six months.
  • Not yet names the frontier but does not raise it.
  • Ahead begins at six months above the child's current age.
  • Months ahead cap at the smaller of 24 months or about one third of the child's age.
  • Not sure and skip create no scored observation.
  • Two real observations are the only current high-confidence rule.
  • Second language is exposure-based and never receives months ahead.
What the score is not
  • Not a percentile or grade level.
  • Not a per-skill mastery probability.
  • Does not weight structured answers above casual chat.
  • Does not decay old evidence.
  • Does not use plan check-offs, hours, or memories.
  • Does not score unanchored graph-walk topics.

Verified gaps and contradictions

Full re-check is blocked after the first report

The onboarding router accepts ?start=childId only when the child has no report token and the checklist is incomplete. The staleness banner sends reported children to that same start parameter.

SMS can run the formal flow only through signup routing

SMS signup can ask one adaptive question per text and resume from stored answers. Linked-family instructions omit the workflow. This is an instruction-routing boundary, not a hard server-side refusal.

The agent can update one item, not run a sitting

record_observation requires a bank item ID, saves one answer, and immediately rescores. There is no active session, current prompt, pause, or resume tool.

Graph walk machinery ships dark

The graph engine, routes, store, and events exist. The authored card registry is empty, no UI calls the route, and unanchored topics intentionally do not affect months ahead.

Conversation continuity is not workflow continuity

Episodes and reply matching preserve conversational causality. They do not own child, scope, current assessment prompt, or completion state.

The record cannot explain a long trajectory

The latest answer overwrites the earlier answer. Report history preserves scores and selected prose, not the full evidence chain or which adult supplied it.

Policy and routing disagree about the app home

The founder registry says the progress report is the authenticated home. The current /app route and first sidebar item still open chat, while /app/report resolves the report.

The one-level-up architecture

Make the model a smart conversation adapter. Keep identity, workflow state, question selection, evidence, and scoring deterministic below it.

Deep module interface Expose one operation such as handleProgressCheckIn(context, command). The command opens, responds, pauses, resumes, or stops. The module hides bank selection, prompt identity, durable state, evidence projection, scoring, events, and channel rendering.

Model responsibility

  • Recognize intent and natural wording.
  • Translate a clear current reply into an allowed answer.
  • Notice an interruption and answer it naturally.
  • Offer to resume without nagging.

Module responsibility

  • Authorize family and re-scope child and session IDs.
  • Own recipient, delivery, revision, idempotency, and concurrency.
  • Reject stale, duplicate, or unrelated replies.
  • Publish deterministic scores once in one transaction.
Deterministic smart targeting For an existing report, ask newly age-relevant checkpoints first, then subjects with fewer than two real observations, then the oldest answered items. Initial onboarding keeps the separate parent choice to go deeper per subject.
Publication and concurrency must be transactional A partial unique constraint permits one nonterminal check-in per child. A racing open returns the existing session. A response is accepted only for the recipient-bound prompt and expected revision. One transaction inserts the response, advances the revision, updates projections, and publishes a snapshot unique to the check-in.

Recommended sequence

Keep the deterministic bank and scorer. Generalize the proven SMS signup question loop, then move current writers behind the new seam.

Slice 1 · Make the existing request work

Add durable child-scoped sessions and immutable responses. Bind each prompt to a recipient, delivery, expected revision, and idempotency key. Use anchored questions only. Add one agent tool for linked chat and SMS, render the same prompt as a web card or text, publish one immutable report snapshot on stop or completion, and fix the staleness re-entry path.

Slice 2 · Put every current flow behind the module

Move onboarding question persistence, SMS signup questions, report corrections, deep dives, and one-item observations behind adapters. Retire direct caller access to saveAnswer, correctAnswers, and createReport.

Slice 3 · Make progress history truthful

Project immutable observations into child_answers. Store actor, source, evidence basis, and session grouping. Move ambient observations behind the same supersession policy and preserve conflicts for confirmation.

Slice 4 · Add smarter depth after content is ready

Author and gate graph-walk cards by subject. Pilot the existing eight-question budget. Keep graph frontier evidence separate from age-anchored scoring. Graduate topics only after reviewed anchors and citations exist.

Do not add in the first slice No top-level Assessment tab, empty graph walk, invented confidence weights, decay, or automatic skill evidence from plan check-offs. Those are separate decisions.
