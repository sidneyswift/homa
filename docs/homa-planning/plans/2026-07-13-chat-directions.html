The chat: four ways the same morning could feel

One surface, four philosophies. Every frame renders the exact same Tuesday: Leo counts to 30 at breakfast, mom sends a photo of Maya's copywork (the new upload ability, shown in every direction), Homa reads it, logs progress, asks one question, and hands back a printable. Design is the only variable. My read going in: direction 1 (Kitchen table) is the launch move, stealing direction 2's attach pattern and direction 4's big-answer treatment for questions. React and overrule.

All names, kids, photos, and numbers on this page are fake sample data.
Today's chat is one 1008-line componentchat-client.tsx owns transcript, queue, dictation, recovery, and the wall. Any direction lands as a refactor into parts, so the redesign and the cleanup are the same job.
SMS already eats photos, PDFs, voice notes, videoThe normalizer turns each into something the model reads. The web channel currently throws non-text parts away. Upload UI + one route + passthrough gets parity.
Nothing stores attachments durably todaySMS media URLs expire; only text captions persist. Web uploads need a home. The family-scoped Vercel Blob pattern from video upload is ready to copy.
shadcn AI Elements: steal patterns, skip the dependencyOur chat runs on eve's hook, not the AI SDK's, and apps/web has no shadcn setup. Its good ideas (attachment chips, stick-to-bottom scroll, collapsible tool lines) port cleanly by hand.

The errand, identical in all four frames: glance mid-lesson, send one photo of a worksheet page, answer one question, print the follow-up page. Judge each direction by how it carries that errand plus an idle scroll while the kettle boils.

Five calls only you can make

1 · What can she attach at launch?

SMS already normalizes photos, PDFs, voice notes, video, and docs into things the model reads. Web can reuse all of it; the question is how much UI and testing we buy before the conference.

2 · After Homa reads a photo, where does it live?

Today nothing durable is stored anywhere (SMS URLs expire; only text captions persist). Web uploads will sit in family-scoped storage either way; this decides whether the photo is findable later or just fuel for one reply.

3 · User bubbles: keep the coral?

Your references both use neutral bubbles (ChatGPT gray, Claude stone). Ours are loud coral. This is the single biggest feel difference between D1/D3 and D2.

4 · Where do suggestion chips live?

Today they float centered in the transcript on a fresh morning. D1 docks them small above the composer; D4 replaces them with the now card's buttons.

5 · Build vehicle for the redesign?

shadcn's AI Elements is real and good, but it assumes the AI SDK's hook and shadcn theming, neither of which apps/web has. Our eve hook already handles streaming, queueing, recovery.

How this wires into the real code (no work started yet)

The frames above are throwaway HTML. When you pick a direction, the build lands in the existing chat surface: apps/web/app/app/chat-client.tsx (split into transcript, composer, and queue pieces on the way), message-parts.tsx (new image and file part rendering), and slash-composer.tsx (attach button joins the pill). File upload reuses proven plumbing end to end: a new /api/chat/upload route copying the family-scoped Vercel Blob pattern from /api/video/upload (path prefix families/{familyId}/chat/, image and PDF types, size caps), the SMS attachment normalizer lib/voice/sms-attachments.ts generalized to accept Blob URLs instead of Telnyx URLs, and the web channel agent/channels/eve.ts passing image and file parts through to the model instead of stripping them (SMS already sends the model these exact part shapes). Durable history keeps the SMS trick: a one-line caption plus the stored file URL as text in conversation_messages, so photos stay searchable and re-showable. Voice notes and video reuse transcribe.ts and Twelve Labs if you pick "everything SMS takes". Tenant isolation guard (pnpm check:isolation) runs before any storage change.
