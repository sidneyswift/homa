The deeper module is child progress

A progress check-in is one evidence-collection workflow. It is not the source of truth and it is not the main product boundary.

Recommended seam A ChildProgress module accepts evidence from trusted callers, updates the live subject → domain → topic projection, and archives the prior projection internally. The agent, check-in workflow, report corrections, and future graph walk all call this module.
1 · Parent words

Journal, chat, formal answer, or correction.

2 · Evidence routing

Concrete skill evidence writes. Activity alone does not prove progress.

3 · Evidence ledger

Append source, adult, quote, time, and answer. Corrections supersede.

4 · Live projection

Recompute subject, domain, and topic readings in the same transaction.

5 · Every reader updates

Agent context, Progress view, plans, and materials read the same current state.

6 · Internal archive

Store snapshots for audit and movement. Do not expose old report pages.

What counts as progress evidence

  • “Maya read a short chapter book and retold the plot” is concrete evidence.
  • “We read for 30 minutes” is an activity and may log time, but it does not prove a reading skill.
  • An assessment answer is structured evidence tied to the current prompt.
  • An ambiguous journal note can trigger one natural follow-up question.

What the parent sees

  • A quiet confirmation chip whenever Homa changes progress.
  • One live Progress view, never a stale report selector.
  • A clear confirmation question when adults disagree.
  • Undo or correction through the same agent conversation.

Important implementation change from the first design Accepted evidence updates the live projection immediately. Stopping a check-in does not “publish” a report. It closes or pauses the workflow, while the answers already saved continue to shape current progress. One internal snapshot is grouped around the sitting to avoid history spam.
Canonical product language The current taxonomy is subject → domain → topic. “Module” is not a progress level in the codebase, so the refined design does not introduce it as a fourth parent-facing term.
Topic-level updates require one skill per prompt Some current bank items bundle separate abilities. For example, math.skip-counting asks about skip-counting and reading 3-digit numbers together. Agent-led check-ins should split bundled items before one answer can update one topic honestly.
