2 · Data model

Four new tables, deny-all RLS (no anon or authenticated policies at all). Every access goes through server routes holding the server-only secret key. The existing waitlist table keeps working untouched: the flow drops a row into it at S1 so the invite machinery keeps one source of truth.

-- migration: lead magnet v2 (names draft)
create table lead_families (
  id uuid primary key default gen_random_uuid(),
  email text not null unique,          -- lowercase, same law as waitlist
  first_name text,
  us_state text,
  source text not null default 'organic',
  utm jsonb not null default '{}',
  resume_token_hash text,               -- hashed, never the raw token
  status text not null default 'open'   -- open | complete | claimed | deleted,
  created_at timestamptz default now()
);
create table lead_children (
  id uuid primary key default gen_random_uuid(),
  lead_family_id uuid not null references lead_families on delete cascade,
  name text not null,
  birth_month date not null,            -- day always 01, mirrors children table
  interests text[] default '{}',
  help_with text,
  band text not null,                    -- computed server-side, e.g. '4y0m-4y6m'
  pending_band boolean not null default false,
  created_at timestamptz default now()
);
create table lead_answers (
  lead_child_id uuid not null references lead_children on delete cascade,
  question_id text not null,            -- 'math.cardinality.3y0m' from the bank
  answer text not null,                  -- easily | getting_there | not_yet | not_sure | skip
  answered_at timestamptz default now(),
  primary key (lead_child_id, question_id)   -- upsert = resume-safe
);
create table lead_reports (
  id uuid primary key default gen_random_uuid(),
  lead_child_id uuid not null references lead_children on delete cascade,
  scores jsonb not null,                -- per-domain {position, months_ahead, confidence}
  bank_version text not null,           -- content-addressed, the M3-04 pattern in miniature
  token text not null unique,           -- unguessable, in the report URL
  generated_at timestamptz default now(),
  emailed_at timestamptz, viewed_at timestamptz, revoked_at timestamptz
);
-- RLS: enable on all four, create ZERO policies. Server key only.
Posture change, flagged for the record: until now the app held no server secret at all (write-only publishable key everywhere). Report generation must read lead rows, so the server-only secret key enters apps/web env (Vercel, type Sensitive, never NEXT_PUBLIC_). The build log anticipated exactly this moment for the invite service; the lead magnet gets there first. Deny-all RLS on lead tables makes the posture stricter, not looser: the isolation script gains cases proving anon and authenticated roles read nothing.
Why the schema mirrors the product's tables on purpose: lead_children.birth_month matches children.birth_month, interests/help_with match the children.profile jsonb keys the walking skeleton already writes, and positions carry provenance. S8.claim is a copy, not a migration puzzle.

3 · Scoring, in plain words

The estimate

  • Every question belongs to a domain and carries the age band where that skill is typical (from the citation-backed bank).
  • easily at her band = at age for that item. easily at the band above = about +12 months of signal. getting there = emerging (half credit). not yet at her band = the domain's growing edge sits here (0-floor months, flagged "growing"). not sure/skip = no signal, never a penalty.
  • Domain position = evidence-weighted average of its items' month-deltas, exactly the template rubric (below_age / at_age / 12mo_ahead / 24mo_ahead) expressed as months. The report prints one number per domain: "+14 mo" or "right in the band" or "growing right now".
  • Confidence per domain = answered items / total items. Below 50%, the domain renders as "not mapped yet" instead of a number. Honesty beats coverage.

Worked example: Maya, 4y 2m, math

  • "Counts past 20 without a wobble" (typical 4y6m) → easily → +12 mo signal, unlocks band-above item
  • "Adds small numbers with objects" (typical 5y0m) → getting there → +5 mo signal
  • "Recognizes written numbers to 10" (typical 4y0m) → easily → at-age signal
  • Domain math: weighted mean ≈ +7 months ahead, confidence high (3 of 3 answered) → gold "Ahead" chip.
  • Same answers always produce the same map: deterministic, unit-tested, zero model calls, versioned with the bank that scored it.
The claims wall (enforced by a content linter in CI): bank items and sentence templates may never contain: behind, delay, disorder, diagnose, screening, assessment, test (as what this is), percentile (until D2 says otherwise), or an em dash. The linter runs on the JSON content the same way the isolation check runs on the schema.
